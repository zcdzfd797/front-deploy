# 需求梳理与优化方案（更新于 2026-04-15）

## 1. 目标

构建一个“低门槛、可追踪、防误操作”的前端部署管理器，覆盖从项目录入、打包、到部署的完整闭环，并确保关键过程在界面内可视化。

## 2. 当前版本信息架构

### 2.1 页面布局

- 左右分栏：
  - 左侧：全局控制 + 项目工作区
  - 右侧：操作终端
- 页面无两侧留白，保证主工作内容一屏内高密度呈现
- 顶部区域仅保留必要信息（日期）
- `刷新` 与 `添加项目` 放在“部署管理器”标题同级位置

### 2.2 主工作区

- 分组导航与检索：
  - 分组切换
  - 新建分组输入框（回车创建）
  - 空分组删除能力（非空分组禁止删除）
  - 分组错误提示高可见（避免被忽略）
- 项目列表：
  - 每个项目卡片提供编辑、刷新 Git、测试连接、打包、部署、删除等动作
  - 删除按钮单独放置在危险操作区域

### 2.3 编辑体验

- 编辑项目改为覆盖在“操作终端”上方展示
- 当前编辑项目卡片高亮标记
- 编辑页主体使用常规主题
- `最新提交 Hash`、`提交信息` 只读，不允许编辑

## 3. 核心交互规则

### 3.1 终端优先反馈

所有关键操作都需在“操作终端”有可见过程与结果，Toast 作为补充反馈。

覆盖范围包括：

- 刷新 Git
- 测试连接
- 打包前校验
- 分支校验
- 打包与部署日志（SSE）
- 关键状态变更（进行中/成功/失败/告警）

### 3.2 打包前 Git 一致性校验（新增强制流程）

点击“打包”后执行顺序：

1. 查询远程 `origin/<当前分支>` 最新提交哈希
2. 读取本地当前提交哈希、提交信息、提交时间
3. 在终端输出远程与本地信息
4. 判断是否一致：
   - 一致：继续
   - 不一致：弹确认框
5. 确认框结果：
   - 是：继续打包
   - 否：终止打包并在终端记录“已取消”
6. 再执行分支校验，通过后进入打包流程

### 3.3 防误操作机制

- 删除分组：仅允许删除空分组
- 删除项目：二次确认
- 部署：二次确认
- 打包：Git 不一致时必须人工确认

## 4. 已落地清单

### 4.1 结构重组

- 移除历史“项目信息/关键指标”等冗余模块
- 全局控制与操作终端改为同级左右分栏
- 扩大分组导航与检索区宽度
- 加宽操作终端区域
- 字体整体放大，并统一到 125% 体验的视觉标准

### 4.2 交互重构

- 分组创建改为输入框回车触发，移除“新建分组”按钮
- 分组提示从弱提示升级为高显著度错误反馈
- 项目卡片动作区重排，`刷新 Git`、`测试连接` 与 `编辑/打包` 同级
- 删除能力独立呈现，降低误触风险

### 4.3 终端闭环

- 测试连接可在终端查看目标信息、认证方式、成功/失败结果
- 打包前 Git 校验可在终端完整查看：
  - 远程与本地提交信息
  - 不一致告警
  - 确认框等待提示
  - 用户选择结果
  - 后续分支校验与进入打包日志

## 5. 后续建议

1. 增加“部署前健康检查”（远端路径可写性、`unzip` 可用性）
2. 增加“发布历史记录”视图（按项目追踪打包/部署流水）
3. 增加“一键回滚”能力（基于备份目录）
