# 需求梳理与优化方案

## 1. 项目目标

为前端项目提供一个“低门槛、可审计、可回退”的部署面板，减少手工登录服务器发布的操作复杂度与人为失误。

## 2. 当前需求基线（As-Is）

1. 项目录入
- 选择本地 Git 项目目录
- 自动读取分支与最新提交信息
- 保存项目记录与备注

2. 发布配置
- 配置构建命令（默认 `npm run build`）
- 配置部署主机、账号与认证方式
- 录入部署路径，支持导入 JSON 连接配置

3. 执行发布
- 点击打包后执行构建并压缩产物
- 点击部署后上传 zip 到服务器
- 自动备份旧目录并解压新包
- 记录部署时间与状态

4. 日志反馈
- 右侧终端显示打包/部署过程日志

## 3. 现状问题（痛点）

1. 交互层
- 反馈方式不统一：大量 `alert` 打断操作流
- 错误提示可读性不稳定，定位问题成本高
- 按钮进行中态与结果反馈不够清晰

2. 设计层
- 视觉层级偏弱，信息密度高时可读性下降
- 桌面与移动端布局适配不足
- 状态信息（可部署/已部署）不够聚合

3. 质量层
- 部分关键操作缺少明确确认与防呆
- 无障碍能力较弱（语义结构、焦点提示、可读反馈）

## 4. 优化后需求（To-Be）

### P0（必须）

1. 统一反馈机制
- 使用页面内 Toast 承担成功/失败反馈
- 终端日志持续输出过程信息，最终状态明确

2. 关键防呆
- 删除、部署必须二次确认
- 保存前校验核心字段（项目名、路径、部署必填项）

3. 无障碍与可读性
- 表单 `label-for` 绑定完整
- 提供可见 `focus-visible`
- 关键区域使用语义化标签与 `aria-live`

### P1（应该）

1. 发布前检查
- 检查部署路径是否可写
- 检查远端命令依赖（`unzip`）是否可用
- 构建目录识别策略可配置（而非仅靠修改时间）

2. 可追溯能力
- 保留每次发布记录（时间、操作者、提交哈希、目标主机）
- 支持快速查看最近 N 次发布日志

3. 体验增强
- 列表支持检索和状态筛选
- 支持项目分组（环境/系统/业务线）

### P2（可选）

1. 回滚能力
- 一键回滚到最近备份目录
- 发布失败自动提示回滚方案

2. 稳定性增强
- 支持并发队列和任务取消
- 支持失败重试与断点续传

## 5. 交互与设计优化原则

1. 信息先后顺序
- 先看“全局状态”（统计）再看“单项目动作”
- 核心按钮固定可见，弱操作放次级样式

2. 操作闭环
- 每个动作必须有“开始、进行中、结果”三段反馈
- 失败提示必须可执行（告诉用户下一步做什么）

3. 视觉一致性
- 使用统一色板、间距、圆角、阴影和动效节奏
- 不使用 `transition: all`，只过渡必要属性
- 保留 `prefers-reduced-motion` 降级方案

4. 响应式与触控
- 关键按钮满足移动端点击区域
- 列表与弹窗在小屏保持可读和可滚动

## 6. 本轮已落地项

1. 页面重构
- 优化头部、概览区、项目列表和终端区结构
- 修复文案显示与内容层级问题

2. 交互升级
- 新增 Toast 反馈，统一成功/失败提示
- 打包、部署按钮增加进行中态
- 强化删除与部署确认流程

3. 可访问性补齐
- 增加 Skip Link、语义化结构、可见焦点
- 终端/通知区加入 `aria-live`
- 表单控件完善标签和可读属性
