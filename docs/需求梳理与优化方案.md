# 需求梳理与优化方案（更新于 2026-09-02）

## 1. 目标

构建一个“低门槛、可追踪、防误操作”的前端部署管理器，覆盖从项目录入、打包、到部署的完整闭环，并确保关键过程在界面内可视化。

## 2. 当前版本信息架构

### 2.1 页面布局

- 左右分栏：
  - 左侧：全局控制 + 项目工作区
  - 右侧：操作终端
- 页面无两侧留白，保证主工作内容一屏内高密度呈现
- 顶部区域仅保留必要信息（日期）
- `刷新` 与 `添加项目` 放在“部署管理器”标题同级位置

### 2.2 主工作区

- 分组导航与检索：
  - 分组切换
  - 新建分组输入框（回车创建）
  - 空分组删除能力（非空分组禁止删除）
  - 分组错误提示高可见（避免被忽略）
- 项目列表：
  - 每个项目卡片提供编辑、刷新 Git、测试连接、打包、部署、删除等动作
  - 删除按钮单独放置在危险操作区域

### 2.3 编辑体验

- 编辑项目改为覆盖在“操作终端”上方展示
- 当前编辑项目卡片高亮标记
- 编辑页主体使用常规主题
- `最新提交 Hash`、`提交信息` 只读，不允许编辑

## 3. 核心交互规则

### 3.1 终端优先反馈

所有关键操作都需在“操作终端”有可见过程与结果，Toast 作为补充反馈。

覆盖范围包括：

- 刷新 Git
- 测试连接
- 打包前校验
- 分支校验
- 打包与部署日志（SSE）
- 关键状态变更（进行中/成功/失败/告警）

### 3.2 打包前 Git 一致性校验（新增强制流程）

点击“打包”后执行顺序：

1. 查询远程 `origin/<当前分支>` 最新提交哈希
2. 读取本地当前提交哈希、提交信息、提交时间
3. 在终端输出远程与本地信息
4. 判断是否一致：
   - 一致：继续
   - 不一致：弹确认框
5. 确认框结果：
   - 是：继续打包
   - 否：终止打包并在终端记录“已取消”
6. 再执行分支校验，通过后进入打包流程

### 3.3 防误操作机制

- 删除分组：仅允许删除空分组
- 删除项目：二次确认
- 部署：二次确认
- 打包：Git 不一致时必须人工确认

## 6. 多对多部署重设计（2026-09-02 落地）

### 6.1 背景与目标

旧模型中每个项目内嵌唯一 `deploy` 对象（服务器 + 凭据 + 路径），项目与服务器严格 1:1，凭据在项目间重复维护。本次重设计支持：

- 一个项目包可部署到多个服务器/路径
- 一个服务器路径可被多个项目包复用

### 6.2 数据模型（projects.json v2）

```json
{
  "version": 2,
  "servers": [
    {
      "id": "uuid", "name": "生产服务器", "host": "…", "port": 22,
      "username": "root", "password": "" , "privateKey": "", "createdAt": "ISO",
      "paths": [
        { "id": "uuid", "label": "官网前台", "deployPath": "/var/www/official", "backupPath": "", "createdAt": "ISO" }
      ]
    }
  ],
  "projects": [
    {
      "…原有字段": "不变",
      "targetIds": ["路径uuid"],
      "deployStates": { "路径uuid": { "lastDeployTime": "…", "deployStatus": "已部署" } }
    }
  ]
}
```

- 凭据只在服务器实体存一份；项目通过 `targetIds` 关联多个路径；`deployStates` 按（项目 × 路径）记录部署状态
- 旧版数据在服务启动时自动迁移：按 `host:port/username` 归并服务器、按 `deployPath` 归并路径，迁移前备份原文件为 `projects.json.v1.bak`

### 6.3 信息架构（v3）

- 中心区新增「按项目 / 按目标」视图切换：
  - 按项目：项目卡片以目标标签（chips）展示全部关联目标，标签含部署状态点，点击可单发部署
  - 按目标：按“服务器 · 路径”分组列出部署到该目标的所有项目，组头支持测试连接，行内支持单目标直发
- 左栏新增“服务器管理”入口：弹窗内维护服务器（含 FinalShell JSON 导入）与部署路径（label / deployPath / backupPath，backupPath 首次获得编辑入口）
- 服务器与路径均支持“上移/下移”排序（首/末位置按钮禁用），顺序持久化并同步影响目标选择器分组与“按目标”视图
- 编辑弹窗的“部署信息”区块替换为“部署目标”区块：已关联目标列表（可解除）+「关联部署目标…」全量多选（按服务器分组，显示占用数）
- 原“复用项目配置”功能删除（被中心化服务器引用取代）

### 6.4 部署交互

- 点「部署」→ 目标多选弹窗（默认全选、全选/反选、计数）→ 分支校验 → 二次确认（含目标清单）→ 一次 SSE 请求顺序部署全部所选目标
- 单个目标失败仅记录并继续后续目标；结束汇总成功/失败数量，终端按 `目标 i/N` 分组输出
- 每目标成功即落盘该目标的部署状态；项目状态支持“部分部署”
- 批量删备份、备份列表均改为按目标维度（先选目标再操作），备份根目录 = `path.backupPath || path.deployPath`
- 备份管理（原“批量删备份”）支持逐项一键回滚：当前线上目录先转存为新备份（回滚可逆），所选备份以 `cp -a` 恢复为线上目录且保留（可重复回滚）；回滚后按目标记录状态“已回滚”并静默刷新备份列表

### 6.5 防误操作

- 被项目引用的部署路径禁止删除（报引用项目名）；存在路径被引用的服务器禁止删除
- 删除服务器/路径均为二次确认
- 回滚与删除备份均为二次确认；回滚的备份目录名按 `目录名_YYYYMMDD_HHmmss` 严格校验并远端复核存在性
- 项目 `targetIds` 在服务端校验过滤（忽略不存在的路径 id）
- 部署前的自动备份统一移动到备份根目录（`backupPath` 优先，缺省部署路径），与备份列表/删除/回滚的检索位置保持一致
